# Lab 07 – Fuzzing for Input Validation Bugs

---

## Overview

This laboratory exercise focuses on identifying input-validation weaknesses in a Python-based Self Storage application using property-based fuzz testing.

The Hypothesis library was used alongside `pytest` to automatically generate a variety of inputs, including edge cases and malformed values. The generated inputs helped identify unexpected application behaviour and input-handling defects.

The application consists of three primary functions:

- `parse_rental()` – Parses the storage unit and rental duration from a formatted input.
- `duration_average()` – Calculates the integer average of comma-separated rental durations.
- `payable_rent()` – Calculates the final payable rent after applying 18% tax and subtracting the discount.

## Objectives

- Understand fuzz testing and property-based testing.
- Explore automatic input generation using Hypothesis.
- Identify input-validation bugs and unexpected runtime errors.
- Analyse failing test cases generated by Hypothesis.
- Implement appropriate input validation.
- Verify application behaviour after fixing the identified issues.

## Implementation

The laboratory exercise was carried out in two stages.

**1. Initial Fuzz Testing**

The original application was executed using representative inputs. Hypothesis-based tests were then developed to generate arbitrary text and non-string inputs.

The initial test execution exposed failures in all three functions. Generated examples included empty strings, missing separators and `None` values, resulting in parsing, conversion and attribute errors.

**2. Application Fixes and Retesting**

The application was updated with input-validation checks to handle invalid inputs in a controlled manner.

The fixes included:

- Validating input types before processing.
- Checking the required separators and input formats.
- Rejecting empty or malformed fields.
- Validating numeric values and rejecting invalid or non-finite values.
- Rejecting negative rental durations and monetary amounts.
- Raising clear `ValueError` exceptions for invalid inputs.

The corrected application was executed again using the same representative inputs, followed by a complete rerun of the Hypothesis test suite.
